# Folder zip test vectors (profile `fyl-folder-zip-1`)

Shared by the browser (vitest) and the Rust CLI (`cfg(test)`) per [docs/FOLDER-ZIP.md](../../../docs/FOLDER-ZIP.md);
both must produce exactly these bytes. Generated by `python3 scripts/folder_zip.py` (stdlib only; a rerun writes
identical files) and checked by `tests/test_folder_zip.py` in `npm run ci`, which also opens every zip with Python's
`zipfile` and, where installed, Info-ZIP's `unzip -t`.

| File | Covers |
| --- | --- |
| `basic.json` | §2, §3: files at several depths, an empty file, a dotfile; empty folders, symlinks (to a file and to `..`) and a FIFO are left out. |
| `names.json` | §2.3, §2.4: bytewise UTF-8 order (U+FF5E before U+1F600, unlike UTF-16), NFC and NFD as two entries, bidi controls dropped (also from a folder name), and names skipped for C0/C1 controls, U+2029, `\`, only dots, only dots and spaces (`. `, `.. ` as a folder, ` ..`; `draft ` is kept), nothing left after dropping, a skipped folder with its contents, and bytes that aren't UTF-8 (`pathHex`). Root `Mappe ü`. |
| `times.json` | §5.1: mtimes before 1970 and 1980, odd seconds, milliseconds, a leap day, the 2038 limit and beyond. |
| `lengths.json` | §2.3: a 255-byte name kept, 256 bytes skipped (file and folder), a 4095-byte path kept, 4096 skipped; a folder of a 4093-byte path entered, one of 4094 bytes skipped as a whole. Not extracted (`disk: false`): such paths exceed `PATH_MAX` under a temporary folder. |
| `zip64.json` | §3, §6: `formula` cases around every ZIP64 threshold (size `U32 − 1` / `U32`, offset `U32 − 1` / `U32`, 5 GiB, the 50 GiB limit) with every byte that isn't data (`segments`: `hex`, then `zeros` for an entry's data); `built`: 65,534 and 65,535 empty files (`many/00000` …), the second needing the ZIP64 end records, pinned by size, SHA-256 and the last 98 bytes; `crc32Combine` for §7.3. |
| `refusals.json` | §2.6: a collision after dropping a bidi control, a file and a folder of the same name after dropping one (not adjacent once sorted), a folder with nothing to send, 100,000 / 100,001 entries, and sizes at and one byte over 50 GiB and P_max. |

Tree vectors: `root` is the folder's name; `tree` lists its items with `path` relative to the folder (`/` separated;
`pathHex` for bytes that aren't UTF-8), contents as `text` (UTF-8) or `base64`, `type` `dir`, `symlink` (with `target`)
or `fifo` (files have none), and `mtimeMs` (default 1793260800000 = 2026-10-29T08:00:00Z; parent folders are implied).
Every tree vector is also written to a real folder by directory handles (Linux; skipped where the file system refuses
or merges names) and walked by `collect()`; `disk: true` ones are also extracted by `unzip`. Expected: `entries` (path in the zip, size, `mtime` = t of §5.1, CRC-32, local header
offset), `skipped` (path relative to the folder, reason `symlink`, `special` or `name`, bytewise order), `fingerprint`
(§9), `size`, `sha256` and the whole `zip` as hex.

Formula cases use zero bytes as data, so their CRC is that of zeros (`crc32_zeros()`); `python3 scripts/folder_zip.py
--check --big DIR` writes them as sparse files and runs `zipfile.testzip()` and `unzip -t` on them (about 6 minutes; the
50 GiB file takes no disk space). Last run 2026-11-06 on Ubuntu 24.04 (UnZip 6.00, Python 3.12.3): all six pass.
